# One reserved "voxelscape" import carries the whole host surface

ADR 0046 gave a place script a bare, attribute-carrying import to name one of
the place's own attached models: `import zombie from "zombie" with { type:
"model" }`. ADR 0048 separately gave a script `import * as engine from
"engine"` to reach `dispatch`/`onTick`/`onPlan`/`log`/and the rest of the
sandbox's host functions, resolved by `bundle.ts`'s own `require` shim rather
than an ambient declaration. This decision folds both into one: a script
depends on exactly one reserved module, `"voxelscape"`, which carries the
whole host surface ADR 0048 gave `"engine"` alongside `createNpc`/`createProp`
for placing and moving a figure wearing an attached model — retiring
`"engine"` as something a script ever names directly.

```ts
import { onTick, dispatch, createNpc, createProp } from "voxelscape";

onTick(function (): void {
  const npc = createNpc({ model: "zombie", id: "zombie-1", x: 0, z: 0 });
  npc.move({ x: 5, z: 6 });
  npc.die();

  const rock = createProp({
    model: "rock",
    id: "rock-1",
    x: 10,
    z: 0,
    solid: true,
  });
  dispatch("toast", { player: "", text: "a rock appeared" });
});
```

`createNpc` and `createProp` are plain factory functions, not classes: each
hands back a plain object closing over its own placement, never something a
script constructs with `new`. `model` is a plain string option, not an import
specifier — a string argument can never collide with a project file the way a
specifier can, so none of ADR 0046's bare-vs-relative reasoning applies here
at all. `id` is never generated by either function: every peer replaying the
same script must compute the exact same id independently (ADR 0026), so it
always has to come from the caller's own deterministic address, the way the
Zombies demo derives one from its population seed and spawn cell.

## Typing a model name against what the place actually carries

`voxelscape.d.ts` declares an empty `ModelsByName` interface and two generic
functions typed against it, alongside the host functions ADR 0048's
`engine.d.ts` declared:

```ts
declare module "voxelscape" {
  export function dispatch<T extends EffectTag>(
    tag: T,
    payload: PayloadFor<T>,
  ): void;
  export function onTick(
    fn: (clockMs: number, eventsJson: string) => void,
  ): void;
  // ...log, now, heightAt, and the rest of the host surface

  interface ModelsByName {}
  function createNpc<K extends keyof ModelsByName>(
    options: CreateNpcOptions<K>,
  ): NpcHandle<ModelsByName[K]>;
}
```

A place's own attached models augment `ModelsByName` live, generated from
their actual bytes (`model-dts.ts` — unchanged in job from ADR 0046, only the
block it emits changed shape); this app's own demo scripts augment it with
one small checked-in file covering every built-in demo's models
(`demo-scripts/models.d.ts`, generated by `tools/generate-demo-model-dts.ts`).
Declaration merging is what makes both additive: `createNpc({ model: "zombie",
... })` narrows to the merged model's real type, naming `"nope"` instead is a
real type error naming the models that do exist, and with no augmentation at
all `keyof ModelsByName` is `never` and neither function is callable. Checked
directly against the real compiler (`ts.createLanguageService`) before this
shipped: two separate `declare module "voxelscape" { interface ModelsByName {
... } }` blocks in different program files merge exactly this way.

A model name unknown to the place at run time — the type caught a typo, but a
script's own type can go stale after a model is removed — is a plain thrown
`Error`, caught the moment the call runs, not a `PlaceBundleError` at bundle
time: `bundle.ts` no longer inspects import specifiers to know which models
are "actually used," so there is nothing left for it to validate ahead of
time.

## Resolving "voxelscape" to a synthetic module, and the real host object underneath it

`resolveSpecifier` recognizes exactly one bare name a project file may import,
`"voxelscape"`, resolved to a synthetic module compiled once through the same
`transpileFile`/`__require` machinery as any project file — the hand-written
standard library (`voxelscape-lib.ts`) plus a generated `__models` table, one
entry per model the place attaches (unconditionally, mirroring
`model-dts.ts`'s own "every attached model, not just the ones some script
imports" choice). That module reaches the sandbox's real host object through
its own import of `"engine-host"` — a second reserved name, resolved the way
`"engine"` itself used to be under ADR 0048 (a magic string `__require`
bridges straight to the sandbox's host object) — and re-exports it whole,
which is how a script's own `import { dispatch, onTick } from "voxelscape"`
reaches functions the synthetic module never itself defines. No project
file's own source has a reason to name `"engine-host"`; only the standard
library's generated source does.

## Considered options

- **Keep `"engine"` and `"voxelscape"` as two separate reserved imports** —
  `"engine"` for the host surface, `"voxelscape"` only for `createNpc`/
  `createProp`. This is what was actually built first, on this branch.
  Rejected: nothing about placing a figure is a separate concern from calling
  `dispatch` — every demo script already needs both together — and a script
  depending on two reserved modules to do one job is one dependency more than
  the job needs.
- **`ScriptedNpc`/`ScriptedProp` as classes, constructed with `new` from a
  model handle a separate `createModel` call returns.** Rejected in favor of
  two plain factory functions taking the model's name directly: nothing about
  placing a figure needs constructor semantics, and a class-plus-separate-
  lookup step was one more moving piece than the actual job required.

## Consequences

- This supersedes ADR 0048's `"engine"` import: a script no longer writes
  `import * as engine from "engine"` — only `"voxelscape"` is a reserved
  specifier a project file may name. `engine.d.ts` is folded into
  `voxelscape.d.ts`; `project.ts`'s `ENGINE_TYPES`/`ENGINE_TYPES_FILE` become
  `VOXELSCAPE_TYPES`/`VOXELSCAPE_TYPES_FILE`.
- `bundle.ts`'s `importsOf` reverts to plain specifier collection; the
  `with { type: "model" }` attribute scanning ADR 0046 added is gone
  entirely, since a model name is no longer a specifier at all.
- `bundlePlaceProject` still takes the place's attached models as a third,
  defaulted parameter, unchanged from ADR 0046.
- Determinism (ADR 0026) holds the same way it did under ADR 0046: `models`
  bytes are a fixed, synchronous input already on `PlaceProject` before
  bundling starts, and decoding them into the `__models` table is a pure
  function of those bytes — two peers still produce byte-identical bundles.
- Every built-in demo script (`gasa4.ts`, `late-to-school.ts`,
  `dont-poop-yourself-at-school.ts`, `zombies.ts`) imports named bindings
  directly from `"voxelscape"` rather than a namespace object, so a name that
  collides with a script's own local variable (`now`, `players`) is imported
  under an alias at the call site instead.
